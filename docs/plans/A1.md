## Goal

Make the repo ready for plan-driven work: Claude Desktop plans, Claude Code implements, `docs/plans/` is the handoff.

## Scope

- `.claude/settings.json` (committed): permissions and an end-of-turn test hook
- `.claude/rules/security.md` and `.claude/rules/testing.md` (path-scoped)
- `.claude/skills/`: `/add-regression-test`, `/security-check-change`, `/end-session`, `/wp-footer`
- `.claude/agents/`: `security-reviewer` (read-only), `test-writer`
- Short "Current work" pointer in `CLAUDE.md`
- `.gitignore`: stop ignoring all of `/.claude/`; ignore only `settings.local.json` and `CLAUDE.local.md`

## Acceptance criteria (status checklist)

- [ ] `claude` starts in the repo and loads the settings, rules, skills and agents without errors
- [ ] `git push`, `gh release` and `scripts/New-ReleaseTag.ps1` are denied by settings
- [ ] The test hook runs only the tests of the module whose Java files changed
- [ ] `CLAUDE.md` stays under ~150 lines

## Instructions for Claude Code

Start a session with: `Execute docs/plans/A1.md` (in plan mode).

```text
Set up this repo for plan-driven work between Claude Desktop (planning) and Claude Code (implementation). docs/plans/ already exists with one file per work package; do not rewrite those files except to tick A1's checklist.
1. First check your own current documentation for: CLAUDE.md @imports, .claude/rules (path-scoped), .claude/settings.json permissions and hooks, .claude/skills, .claude/agents. Use only features that exist in your installed version.
2. Add a short "Current work" section to CLAUDE.md pointing to docs/plans/README.md (keep CLAUDE.md under ~150 lines; move detail into imported files).
3. .claude/settings.json (committed): allow mvn and git status/diff/log/branch/checkout/add/commit; deny git push, gh release, scripts/New-ReleaseTag.ps1, and reading *.token, .env and credential files. Add a hook that runs `mvn -B -q -pl <module> -am test` for the module whose Java files changed, at the end of a turn (not after every single edit).
4. .claude/rules/security.md scoped to ServeCommand, McpCommand, RunCommand, ValidationTools, ExcelTools, archive/zip code and the Main ai package: never weaken the egress policy, fail closed on failed imports, every change needs a regression test.
   .claude/rules/testing.md scoped to **/src/test/**: no network, @TempDir, fixtures under src/test/resources/fixtures/<feature>/, snapshot updates only via -Dsnapshot.update=true.
5. Skills: /add-regression-test, /security-check-change (checklist from SECURITY-SELF-ATTESTATION.md §5.3 item 5), /end-session (tick the plan checklist + update PROJECT.md), /wp-footer (the standard footer in docs/plans/README.md).
6. Agents: security-reviewer (read-only tools; reviews a diff against the security rules), test-writer (writes tests for a named class using the fixture rules).
7. .gitignore: replace the blanket /.claude/ ignore so settings.json, rules, skills and agents are committed; ignore .claude/settings.local.json and CLAUDE.local.md.
```

Standard footer (applies to every work package):

- Read CLAUDE.md, docs/PROJECT.md and this plan file first. Do not redo full codebase discovery.
- Start in plan mode: propose the plan, list the files you will touch, wait for approval.
- Work on branch feature/<wp-id>-<short-name> off devel. Do not push, tag or open a PR unless asked.
- Follow CLAUDE.md conventions (license header, package case, JPMS requires, logic in Core).
- Tests first where possible. Finish with `mvn -B verify` green and report the test count before and after.
- Run /security-review on the diff if the change touches I/O, network, processes, parsing or serve/mcp/run.
- At the end: tick this file's checklist, add to its decisions log, update docs/PROJECT.md (date, status, known issues, next steps) and docs/cli/* if CLI behaviour changed. Summarise what changed and what is left open.
